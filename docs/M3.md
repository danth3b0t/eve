# M3 — recovery and synchronization

**Status: journaled `resume`, bounded `gc`, and additive key/extra-endpoint `sync`.** EVE continues creation/destruction and applies exact garbage cleanup; sync preserves every established endpoint allocation while appending supported mappings. Only migrations that alter existing service/resource topology require a new workspace.

## Resume boundary

- `eve resume [workspace]` resolves a branch, canonical path, UUID or invoking worktree, acquires its durable operation lock, and uses the already recorded workspace ID, revision, target manifest, resource references, deployments, generation and allocation. It never invokes `PlanGit` again or chooses a replacement workspace/resource.
- Repeating `eve create <branch>` for an existing prepared workspace returns the same workspace with `existing: true`; `--from` cannot retarget it. An incomplete operation rejects with `E_RESUME_REQUIRED` and is never silently replaced.
- A first-stage local interruption may take a new source file snapshot; provider/resource identities and the target commit stay frozen. Once protected staging exists, resume verifies those original image/HMAC records instead of regenerating them.
- Unknown deployment-create states re-read only the exact recorded reference before adoption; one duplicate create is not allowed. Deploy keys and image journals are used only when their complete metadata matches.
- Prepared workspaces only reconcile their finished file journal; they do not republish over later user edits. Destroying/cleanup-pending workspaces retry `DestroyLocal` under the same endpoint/Git ownership checks and require free claimed ports before allocation release.
- State with `failed`, Git reconcile, missing HMAC key/images, replaced registry, changed source/Git identity, or a dirty workspace remains diagnostic. `resume` does not infer consent beyond the explicit command, and it never runs a periodic cleanup.


## Bounded sync boundary

- Allowed: adding env keys or extra listener mappings, and changing values for the **same** services, destinations, resource projects, providers, TTLs, allocations and branch identity. Existing endpoint slots/ports never move; a new extra endpoint probes and appends a later slot inside the already frozen block. Byte-identical no-ops return without a generation increment.
- Rejected: moving keys/files/listeners, changing a block size, removing a value or resource/service, updating a project/profile/TTL/region, or retargeting resource identities. Those operations require `E_CREATION_ONLY_CHANGE`, a new workspace, or the unimplemented broader lifecycle.
- Drift is checked before any remote write. A changed EVE-managed value fails as a user conflict unless `--overwrite-managed`; unmanaged bytes, comments and values continue to be owned by the project. An updated branch may leave a valid `E_WORKTREE_DIRTY` before remote mutation.
- Only the declared `resources.<id>.env` values are compared and uploaded through exact resource/project identity. Convex deploy keys are reread from existing protected references; no key rotation or replacement occurs merely to sync. A remote write error remains diagnostic and does not silently replace the backend.
- Generation commits happen in one short SQL transaction after verified file publication; later destroy honors the current generation rather than asking for generation-1 images. A changed local process is never restarted automatically, and every meaningful change reports `restart_required=true`.


## Garbage collection boundary
- Plain `eve gc` is report-only. Its default scope prints `all_repositories`; `eve gc --workspace <uuid>` limits report and optional apply to exactly that registry identity.
- Bare reports carry independent observations for lifecycle kind, local path presence/absence, recorded expiry and remote cleanup state. A past expiry never authorizes local worktree removal or disguises an absent recorded path as a mere expired resource.
- Manual worktree loss is finalized through a new durable destroy operation. Remote deletion happens before claim release; a recreated or inaccessible path refuses without claiming absence. Existing branches, out-of-band deployments, source directories and expired-but-present workspace files are never garbage-collected.
- `--apply` continues after recoverable candidate failures when other exact identities remain intact, and emits per-candidate results plus `E_GC_PARTIAL` instead of replacing earlier successes with only a late error.
- The contract-fake Convex lifecycle proves remote deletion and private key purge after manual worktree loss. Exact remote names/references/spec fidelity remain required; reports never include deploy key/selector values or unmanaged local files.

## Evidence

- Lifecycle tests cover resume from allocation/Git intent, frozen UUID/path/manifest, unmanaged source input, provider `unknown`, exact deploy binding, public output, protected image publication and completed idempotent resume.
- External CLI tests create the checkpoint in one process, run a separate `eve resume --json` process, and verify the original UUID/path and native image publication.
- Existing interruption suites still cover durable staging/rename receipts and lost local/Git response reconciliation.
- GC tests prove an existing/recreated path blocks everything, an exact manually removed local workspace finishes only after absence evidence, and a Convex deployment/key can be deleted through the same new durable destroy intent.
- Sync tests verify additive user/remote keys, retained unmanaged content, drift refusal and explicit overwrite, exact remote env updates with an unchanged deployment, idempotent generation handling, and post-sync destruction with the latest postimage.

## Not implemented

Broader topology `sync`, drift-aware broader remote reconciliation, broader garbage preview/provider reconciliation, out-of-band resource/key loss repair and exhaustive crash recovery matrices remain open. Interactive create review and an elapsed 31-minute TTL are now implemented/tested; schema v2 migrations exist for durable resource/sync attempt journals and workspace applied-manifest/generation storage.
