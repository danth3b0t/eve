# M4 — onboarding and diagnostics

**Status: bounded `init`, plan/list/doctor diagnostics with typed create review.** A non-TTY cannot receive interactive approval; automation uses `--yes` or JSON without prompts. Broader discovery/layout awareness remains pending.

## Plan boundary

- `eve plan <branch> [--from]` uses the canonical committed manifest, never source working-copy overrides. It runs the same bounded Git, raw-file/tracking/ignore and lexical path preflight used by create and returns branch, source, target commit, manifest hash, prospective destinations and declared resource/service structures.
- Portblocks, allocations, workspace UUIDs, worktrees, remote references, HMAC keys, credentials and provider objects are all intentionally absent. A successful plan only means the committed inputs passed read-only evaluation; it does not prove loader behavior, port availability, provider permission or permission to mutate.
- The command does not initialize/open EVE's protected registry, launch the project, fetch provider state or display private file contents. Structural reports include declared env key names and paths, never local deployment keys or unmanaged values.
- An interactive `eve create` contacts that same preview first, and typed `yes` alone moves into durable intent. Stderr contains no env values or secrets, cancellation wins, and an empty answer, offline input or non-TTY refuses without mutation. State opening and source registration wait until approval.


## Init boundary

- The supported pattern is deliberately tiny: committed Bun/Vite package(s) whose exact dev script is `vite`, whose configuration contains `loadEnv`, a `PORT` reference and `strictPort`, plus direct committed `convex.json` packages. Nonmatching packages are **unsupported layout**, not partially converted.
- Proposals include only the evidence-derived destination path/name, existing public VITE URL keys and an explicit `--project team:slug` when Convex is found. No code executes; no local dotenv values, credentials, loader details, package installs or root scripts are inherited or guessed. Ignore requirements must already exist.
- `--write --yes` creates only `eve.toml` (exclusively, `0600`, synced) as an untracked review file; it never edits code/scripts/ignore rules, stages a commit, writes state or provisions resources. `--dry-run` and default proposals make no mutation.
- The generated comments require review: EVE still validates the manifest/Git/filesystem and provider identities during `plan`/`create`.

## List boundary

- Default scope is the explicitly registered canonical source associated with the invoking checkout (including a linked worktree). Registered metadata alone is not rechecked ownership, so create/resume/destroy still verify Git and filesystem identities independently.
- `--all` enumerates every registered repository in the user registry. Listings include only live workspaces by default and deliberately omit `destroyed` tombstones. A workspace row carries ID, branch, path, state, phase, generation, public ports/URLs and public Convex identity/expiry.
- The command opens the existing database read-only, creates no schema/lock/profile objects and performs no network, Git mutation, port release, file image creation, or provider inference. Values/selectors and deploy credentials are never emitted.
- Output remains additive-compatible JSON schema version 1; groups may gain fields but current `workspaces`, IDs, paths, states, endpoints and resources stay public metadata.
- Empty groups report `no live workspaces`; concurrency races in reads are a diagnostic, not an authorization to repair.

## Doctor boundary

- Every check has one of `pass`, `warning`, `fail`, `not_checked`. The project is never launched/run, and static load checks stay `not_checked`. A listener is at most a warning, never process identity/health proof. Changing endpoints are not fixed automatically.
- Registry/Git checks verify recorded workspace state, branch/path identifiers and the current committed manifest. Updated branch revisions with file edits become warnings rather than authorization; visible Git changes block lifecycle mutations before any provider write.
- File checks compare every current managed destination's bytes and privileges against the published generation HMAC. Differences are warnings when a narrower sync may still accept them; missing/unsafe destinations are failures. Remote doctor verifies only exact project/deployment/reference/name/type/default/expiry through the management API; no environment values, deploy keys or broad project reads are used.
- JSON keeps check IDs, paths, states, expiry evidence and runtimes public. Unmanaged/untracked file contents, database rows and secret selector values are never printed.

## Evidence

- An external CLI test proves plan JSON exposes branch/target/file structure while creating no registry database or worktree.
- Init tests reject existing manifests and manifest-less layouts, prove the supported Vite/Convex pattern with `--project`, validate dry-run/write consent and `0600` ownership, and then run plan after a manual commit without creating EVE state.
- A real CLI test registers a repository, creates one native workspace and verifies `list` and `list --all` JSON with the repository label, assigned service port and workspace UUID/path.
- Destroying that workspace removes it from the default read-only list while keeping its branch and any audit tombstones outside the report.
- Doctor tests pass without a running application, then report file drift and visible Git changes as warnings while runtime/loader remain `not_checked`. Contract-fake Convex remote checks match exact identity without env/key queries. CLI output is tested for pass and `not_checked` diagnostics.

## Not implemented

Broader framework discovery and interactive onboarding UX remain next. Loader support beyond the proven exact Bun/Vite/Convex pattern must not be inferred from these checks.
