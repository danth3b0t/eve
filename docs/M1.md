# M1 — configuration foundation

**Status: partial.** The Linux launch/API boundaries are demonstrated in [M0.md](M0.md), with defaults/platform acceptance still open. This slice implements pure configuration handling, not a runnable EVE CLI or the complete local-core milestone.

## Implemented

| Package | Contract |
|---|---|
| `internal/config` | Bounded, strict v1 TOML decoding; defaults only for omitted fields; identifiers, keys, copy-pattern vocabulary, lexical containment, TTL overflow, endpoint capacity, reserved keys, and reference existence. Also validates the separate user port-range config. |
| `internal/interpolate` | Only the specified public references and `$${` escape; no process env, file access, evaluation, env-to-env lookup, recursive expansion, or credential outputs. Errors return no partial value or source excerpt. |
| `internal/resolve` | Uses supplied stable allocations/public provider outputs; brackets IPv6 URLs; merges identical shared-file values; reports all owners of a conflicting key; preserves per-binding tracked-file consent. Remote JSON values remain distinct from local dotenv values. |
| `internal/envfile` | Bounded lossless dotenv parsing and in-memory image preparation. Replaces only owned value spans; preserves unrelated bytes, comments, quoting, multiline content, BOM and line endings; appends missing keys in sorted order; rejects targeted duplicates, ambiguous syntax, and unrepresentable generated values. |

`go-toml/v2` is pinned at **v2.4.3**. Its `DisallowUnknownFields` mode still matches struct field names case-insensitively, so EVE additionally checks exact TOML tags. Environment-map key casing is preserved. Decoder error excerpts are not forwarded because they can contain values.

Input bounds: manifests/user config 1 MiB; dotenv input/output and interpolation input/output 2 MiB. Bare CR, alternate colon assignments, and ambiguous unquoted escape/quote boundaries are rejected rather than guessed. This is not a shell parser. The interpolation escape can produce a literal `${...}`, but that remains unrepresentable in a generated **local** dotenv value; remote JSON values have a different serialization contract.

## Evidence

- All bundled manifest examples pass Go structural/semantic checks.
- Unit tests exercise missing/unknown/duplicate/miscased fields, unsafe lexical paths, references, limits, TTL/range boundaries, reserved keys, collisions, serialization/redaction, stable supplied allocations, and exact lossless images.
- Parser fuzz targets cover TOML, interpolation, lexical paths, and dotenv round-trip/idempotence. Bounded runs completed without failures; this is not exhaustive proof.
- `EVE_M0_NATIVE=1` additionally loads M1-produced CRLF/quoted-source file images through the fixture's unchanged Bun/Turbo/Vite frontend launchers and verifies actual listeners/public browser-module values.
- `go test ./...`, `go vet ./...`, `EVE_M0_NATIVE=1 go test -race ./... -count=1`, and `CGO_ENABLED=0 go test ./...` passed on Linux/amd64. The separately opt-in live test still fails its missing-default-marker checks.

## Not implemented by this slice

A successful parse or resolved image is **not** a prepared workspace and does not authorize any write. In particular:

- Lexical normalization is not filesystem canonicalization. Symlinks, hardlinks, case aliases, actual directory identity, Git tracking/ignore rules, copy expansion/limits, and races still need filesystem/Git checks.
- Allocations are inputs, not reservations or socket leases. SQLite state, source registration, advisory locks, concurrent allocation/probing, and Git lifecycle are pending.
- Images are not published. Protected staging, atomic replacement, multi-file journaling, HMAC drift checks, interrupted-operation handling, and deletion safety are pending.
- Public resource outputs do not contain keys. Production provider validation and private native selector/credential bindings remain M2 work; the M0 cloud probe is test code only.
- No `create`, `path`, `status`, or `destroy` CLI exists yet. M1's next slice is durable local state/Git/file publication, not additional cloud features or release packaging.
