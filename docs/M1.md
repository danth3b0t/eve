# M1 — local-core foundation

**Status: local-only core is functional with remaining platform/recovery gates.** The guarded EVE CLI creates real worktrees, publishes native configuration, reaches `prepared`, reports path/status, and destroys exact local-only workspaces. Two CLI-created native worktrees launch through unchanged Bun/Turbo/Vite commands; one can be stopped and destroyed while the other remains running. Production Convex, sync/resume/gc/discovery, interactive plan approval and full release hardening remain pending.

## Configuration boundaries

`go-toml/v2` is pinned at **v2.4.3**. Its strict mode still matches struct names case-insensitively, so EVE additionally checks exact TOML tags. Environment-map key casing is preserved. Decoder excerpts are not forwarded because they can contain values.

Input bounds: manifests/user config 1 MiB; dotenv input/output and interpolation input/output 2 MiB. Bare CR, colon assignments and ambiguous unquoted escape/quote boundaries are rejected rather than guessed. This is not a shell parser. Escaped `${...}` can be a literal interpolation result, but remains unrepresentable in a generated **local** dotenv value; remote JSON has a different serialization contract.

## Durable state and allocation boundaries

- `modernc.org/sqlite` is pinned at **v1.58.0**, with its required **v1.75.6** `modernc.org/libc`. No SQLite executable/server or CGo dependency is introduced. `go.mod`/`go.sum` pin the complete dependency set.
- The initial, **unreleased** v1 schema now also records source/common-directory filesystem identities and the `EVE1` SQLite application ID. Common-directory identity is unique independently of path spelling. This is an initial schema revision, not an implemented upgrade path. Future migrations require a consistent backup and transactional migration before mutation.
- Every connection receives foreign keys, `synchronous=FULL`, a 5-second busy timeout and immediate write transactions. WAL is enabled only after the registry format/version check. State permission checks use `lstat`, not opening/closing a live database or SHM file, which could drop POSIX SQLite locks.
- Directories require `0700`; database/sidecars/lock files require `0600`. Existing broad permissions, links, special files and replaceable ancestor namespaces fail rather than being silently repaired. New directory entries are synced where supported. Permission bits are not protection from the current user or root.
- Linux's bounded filesystem policy covers ext2/3/4, XFS, btrfs, ZFS, tmpfs, F2FS and overlayfs with local locking-capable backing storage. macOS selects local APFS/HFS+. Arbitrary FUSE/network/shared storage is not supported. Tmpfs is volatile; use persistent local storage outside tests. Actual macOS filesystem/locking behavior still requires runtime validation.
- State registration remains a **metadata primitive**. The lifecycle layer establishes Git membership and reuses the registered source, never the invoking linked worktree. `OpenForGit` rejects state inside known checkouts/Git metadata (including aliases) before calling the mutating opener. Explicit registration consent/UI belongs to the caller. Read-only command opening remains pending.
- A workspace lock lives across the operation; repository locks come next, then short SQL transactions. No Git/network/socket probe occurs inside a write transaction. Lock files are never unlinked to unlock, and PID/timestamp guesses do not authorize takeover.
- Candidate claims, accepted slots and phase progress survive process death. A pending candidate is re-probed, not called ready. Only an observed occupied-port result can discard a pre-Git candidate; unexpected errors retain it. Accepted blocks have no failure-release/reallocation API. No listeners means no block or probes.
- Allocation `Ready` means **reservation accepted**, not workspace `prepared`, socket ownership or application health. Accepted ports still need a final recheck before publication. Destruction-time release and topology additions belong to later lifecycle work.
- Stored manifests contain reviewed manifest data, never copied dotenv images or provider credentials. Snapshot fields are excluded from ordinary JSON results; SQL diagnostics do not include raw SQL or values. The machine HMAC key and image staging now use protected objects; production provider credential profiles remain unimplemented.

## Git boundaries

- `PlanGit` selects the registered source's HEAD (or explicit `--from`) for a new branch, and an existing branch's own tip otherwise. It reads and validates the committed `eve.toml` blob, not dirty working-copy overrides. Checked-out branches, sparse checkout, submodules and hidden index flags are diagnosed. Planning creates no worktree directories or reservations.
- Git uses argument vectors and a restricted environment; ambient Git retargeting/config injection, tracing and application/provider credentials are not inherited. Output is capped at 8 MiB; stderr/error output is withheld. Mutations use a temporary empty hooks directory outside checkouts; fsmonitor and automatic maintenance are disabled. Ordinary checkout filters remain possible, so this is **not** an untrusted-code sandbox.
- The creation operation UUID supplies a temporary `eve-create:` native Git lock reason, never a launcher marker or a substitute for OS-held locks. Git writes that reason **before checkout completes**. Reconciliation therefore also requires matching identities/ref, a clean checkout, a stable regular index and no index lock. Incomplete/edited/unknown paths remain unresolved; no automatic reset, prune, adoption or claim release occurs.
- The actual checkout/common/admin paths and filesystem identities are persisted before removing EVE's temporary Git lock. Failed/lost responses retain inflight/unknown intent. Exact completed receipts can be reconciled without repeating `worktree add`; other partial initialization requires later recovery work.
- Removal primitives refuse identity/branch changes, unrelated Git locks, index locks and visible user edits unless explicitly discarded. A future materializer may approve only exact owned unstaged tracked edits; HMAC implementation is not supplied by this callback. Branches are preserved and ignored-file/cache loss is surfaced as a warning.
- Git identity alone is **not deletion authorization**. Registry ownership, registered-source protection, endpoint/launcher checks, consent, remote cleanup ordering and transactional claim release must be integrated by the future destroy lifecycle. SQL/OS-lock crash tests are not proof of full Git or power-loss recovery.

## Read-only file boundary

- `PlanGit.Files` snapshots selected native destinations and explicit copy inputs from the **registered** source using the pinned target manifest. Dirty tracked source bytes are never copied: their target counterpart is used, or its absence is a conflict. Untracked source data cannot overwrite a tracked target. Only selected native files are automatic candidates, not `.env*` siblings.
- Original path components are checked before normalization, including `link/../file`. Reads use Go's descriptor-backed `os.Root`, bounded reads and no-follow/nonblocking opens. Links are conservatively refused, sources must be regular, and destinations must not be hardlinks. Known Git, Node dependency and local Convex state directories are excluded. This remains no sandbox against the current user/root or arbitrary mount manipulation.
- Copy selection is case-sensitive, includes dotfiles, and supports `*`, `?` and `**` over files. Exact missing paths fail; unmatched globs are reported. Glob components containing `.`, `..` or empty segments are diagnosed rather than guessed. Limits: 10,000 selected files, 256 MiB copied/native-input or final-image bytes, 100,000 cached directory entries and one million discovery visits per expansion pass. Narrow an overbroad manifest rather than silently truncate. Whole batches/preimages occupy memory; 256 MiB is not a peak-RAM guarantee.
- Existing filesystem names must have exact spelling. Case/Unicode-normalization checks use `golang.org/x/text` **v0.42.0**. Ambiguous variants of not-yet-existing destination components are conservatively refused even on case-sensitive hosts; distinct existing case-sensitive names are permitted. Actual macOS filesystem acceptance remains pending.
- Snapshot validation re-enumerates selections and compares file identities, modes, sizes and contents, not timestamps alone. New matches, changed tracking or edited inputs require a fresh reviewed plan. Reports, JSON and ordinary debug formatting omit image/preimage bytes and values; parser errors add safe file/line context.
- `files.Plan.Prepare` rechecks the actual linked checkout's pinned ref, paths, tracking and Git ignore rules, then constructs local-only final images with the existing resolver/lossless writer. Tracked native files require unanimous consent; tracked credential destinations always fail. New local configurations must already be ignored. Git `check-ignore` rejects the global `--literal-pathspecs` flag, so this concrete-filename query explicitly disables it and prefixes `./`.
- All returned configuration images request `0600`, but **no mode or file is changed**. Resource images are refused until verified private native bindings exist; source selectors are not returned as final resource images. Provider/ambient-selector and launcher compatibility audits remain separate gates.
- These in-memory snapshots alone are **not durable staging or publication authorization**. The staging and publication lifecycles below establish those separate boundaries.

## Protected staging boundary

- `Store.HMACKey` serializes initialization with an OS lock and records a random 32-byte key's opaque reference and high-entropy checksum **before** writing it. Complete lost-response writes can be re-synced and verified; missing, partial or changed keys are never silently regenerated. Unresolved initial key writes require reviewed recovery, not automatic rotation.
- `StageFiles` prepares the whole local-only batch, then journals all preimage/postimage references, file identities, modes, sizes and per-file/per-value HMACs before sensitive writes. Objects are exclusively created, synced and reread before SQL acknowledges `staged`. File journals contain no image bytes or plaintext managed values; the existing reviewed manifest snapshot is unchanged. Existing schema tables are reused without a schema revision.
- Completed staging advances only to phase `publish`, still `creating`, generation `0`. Reentry ignores source snapshots and verifies recorded objects. Missing/partial/corrupt objects retain the inflight intent; no automatic restaging, unlinking, port release or new worktree occurs. Snapshots remain protected until durable publication completion.
- Limits: 10,000 images; 256 MiB each for aggregate preimages and postimages; 16 MiB journal metadata. Object references are canonical UUIDv4 filenames; roots are private, identity-checked, local filesystems. Files require one link, correct owner/type and `0600`; existing unsafe objects are refused, not repaired. HMAC-SHA-256 uses versioned, length-framed file/value/workspace/path domains.
- `StagedImage` verifies a private image, **not permission to replace a destination**. Staging itself writes no application files; the publisher independently checks mutation-time policy.

## Initial publication boundary

- `PublishFiles` rereads all protected images, checks file/value HMACs against frozen resolution, verifies Git identity/ref/locks, tracking, ignore rules, consent and paths, then re-probes endpoints. Publication intents precede parent/temp creation. Missing parent directories use `0700`; sibling temps use exclusive `0600` creation.
- Complete synced temp identities are journaled **before** rename. Pinned parent descriptors and fresh checks guard replacement. New destinations use Linux `RENAME_NOREPLACE` or macOS `RENAME_EXCL`, without an overwrite fallback. Existing tracked destinations require their exact preimage identity/content. Each rename is followed by parent sync and exact postimage verification.
- Reentry accepts only exact receipted temps/postimages. Unreceipted or partial temps, changed files, staged edits, unrelated visible changes and changed Git locks are refused. Errors preserve the operation and allocation. A full-batch recheck surrounds publication; large-copy performance is not yet validated.
- Only complete publication and final endpoint/file verification commit generation `1`, per-file/per-key fingerprints, ownership and `prepared` in one SQL transaction. Literal values are conservatively private; unknown copy provenance remains NULL rather than implying whole-file ownership. Protected images are removed individually by verified reference after completion. Lost cleanup responses reconcile absence; completed reentry never republishes over later user edits.
- Multiple file renames are **not one atomic filesystem transaction**. The caller must approve the native launch contract and wait for completion before starting the project. Concurrent same-user/root edits or mount manipulation are not sandboxed. `prepared` records configuration completion, not runtime health. Drift-aware sync and provider destruction remain separate work.

## Local destruction and CLI boundary

- `DestroyLocal` supports completed LOCAL-ONLY generation 1 and the exact inflight/cleanup-pending cycle it created. It refuses unapproved or provider manifests and never authorizes deletion from Git identity alone. Preflight verifies registered source/common identity, Git locks/branch/index, declarations, files and endpoint ports before persisting `destroying`.
- Visible tracked modifications are discarded only when their current regular-file mode/content exactly matches the recorded generation-1 postimage HMAC. Later edits or nonowned visible files require `--discard-changes`. Ignored files remain absent from Git change evidence; destruction always warns that they will be removed. A listener rejects destruction with `E_POSSIBLY_RUNNING`; `--assume-stopped` only acknowledges user assessment and never kills a process.
- The workspace lock precedes the repository lock, and short SQL never spans Git. The destroy operation is durable before removal. Removal response loss is finalized only after proven checkout/admin absence. Post-removal endpoint occupancy becomes `cleanup_pending`; claims stay held until a later invocation verifies both absence and free endpoints. A replaced path blocks claim release.
- `state.OpenReadOnly` is only an existing-registry reader: no missing root/schema/lock/HMAC creation, no workspace capability lock, and SQL query-only checks. It still reads protected owner-only paths rather than offering sandbox or encrypted-at-rest semantics.
- `eve create --yes` registers an unregistered canonical source only after that flag, then re-plans and completes the reviewed local boundary. `destroy --yes`, `--discard-changes` and `--assume-stopped` remain distinct. An interactive plan-review UI is not implemented. A committed `eve.toml` follows target branch/ref semantics, never source working-copy overrides.
- CLI selectors accept branch, canonical path, full UUID, or the invoking worktree. Human output contains only IDs, paths, states and endpoint URLs; `--json` emits one versioned object. There is no raw environment dump. A live match of a destroyed worktree is denied; destroyed branches stay in Git.
- This is no complete recovery UX. Interrupted Git/key/staging/unreceipted publication data remains diagnostic; full `resume`, `sync`, `gc`, provider identity, loader guidance, diagnostics and macOS runtime proof remain later work.

## Evidence

- All bundled manifests pass Go validation. Unit tests and prior bounded fuzz runs cover parsing, references, limits, serialization/redaction, collisions and lossless images.
- Real SQLite tests cover connection pragmas, FK/uniqueness/immutability constraints, private modes, registry identity, unsupported-schema refusal without rewriting the database, and cancellation without state creation.
- Real-process tests cover concurrent fresh initialization under umask `000`, six allocators across two repositories, SIGKILL release of workspace/SQL locks, retention of committed claims, and rollback of an uncommitted transaction. These are process-crash tests, not power-loss or complete lifecycle recovery proofs.
- Real IPv4 and IPv6 sockets verify wildcard conflict detection, occupied unused block tails, socket release and late conflicts without reallocation. Injected probes additionally cover inclusive port 65535, exhaustion, interrupted re-probing and absence of SQL transactions during probes.
- An already-cancelled context did not stop Go's numeric-address listener on this host. Explicit cancellation checks now cover that case.
- Real Git repositories cover committed-manifest selection, source HEAD movement, existing-branch conflicts, unsupported layouts, newline/Unicode paths, hook/fsmonitor suppression, dirty/staged/untracked files, user locks, identity replacement and branch preservation. A blocked real checkout filter exposed premature receipt adoption; the strengthened observation now refuses it, and cancellation terminates Git's process group.
- Real Git/SQLite integration verifies registered-source reuse from a different worktree, durable intent before mutation, no SQL transaction during Git, response-loss reconciliation without duplicate creation, refusal of matching-but-unowned paths, and state-location rejection before any contained state is created. These are internal lifecycle tests, not a native-launch CLI acceptance test.
- Real file/worktree tests cover selected-only copies, dirty tracked source isolation, target-specific/global ignore rules, private output formatting, links/FIFOs, nonadjacent file/parent collisions, missing-path aliases, copy limits and edits with restored timestamps. The lifecycle rejects malformed owned input before returning a creation plan. No native files are written by these tests' production APIs.
- Protected-object tests cover modes, unsafe links/types, replacement, bounds, cancellation, concurrent key initialization and missing/changed-key refusal. A fixed HMAC vector was derived independently. Real Git/SQLite staging tests verify private images/preimages, no target writes, corruption with restored timestamps, and SIGKILL after partial/complete object sets followed by exact reconciliation or refusal. They do not establish power-loss or publication recovery.
- Publication tests cover mutation-time parent substitution, exclusive no-replace rename, occupied endpoints, late file/ignore/lock changes, transactional generation completion and ownership-limited cleanup. SIGKILL after temp receipt or rename preserves evidence; exact postimages reconcile without another rename, while later user edits fail.
- `TestPublishedLifecycleNativeFrontends` proves production lifecycle publication through unchanged frontends. `TestCLILocalLifecycleNativeFrontends` builds the real CLI, creates two isolated native worktrees, verifies unchanged Bun/Turbo/Vite listeners/public values, destroys one **stopped** workspace while the other remains running, retains its branch, and leaves source/remaining worktrees unchanged except generated ignored configuration. Dependency installation and process supervision stay in the test harness. This remains local-only, not browser execution or Convex acceptance.
- CLI and destruction tests cover explicit `--yes`, branch/path selectors, JSON output, dirty/nonowned work refusal, exact EVE-tracked edits, listener refusal, `E_CLEANUP_PENDING`, replacement-path blocking, claim release, branch/source preservation and removal-response reconciliation. Stopped probes now wait up to 75 seconds where socket lifecycle may retain the port after process exit; the harness closes HTTP client connections first.
- `go test ./...`, `go vet ./...`, `EVE_M0_NATIVE=1 go test -race ./... -count=1`, repeated core tests and `CGO_ENABLED=0 go test ./...` pass on Linux/amd64.
- CGo-disabled `eve` and test executables build for `linux/amd64`, `linux/arm64`, `darwin/amd64` and `darwin/arm64`; file formats were inspected. Only the Linux/amd64 implementation was executed, and these remain development builds, not release artifacts.
